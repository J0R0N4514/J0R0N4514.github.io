# Alagan Market — HTML prototype

## Запуск
В корне проекта выполните `python -m http.server 8000`, затем откройте http://localhost:8000. Не запускайте index.html двойным щелчком: браузер может заблокировать загрузку JSON.

## GitHub Pages
Загрузите содержимое этой папки в корень репозитория. В Settings → Pages выберите Deploy from a branch, ветку `main`, папку `/ (root)`. После публикации используйте HTTPS URL.

## Telegram Mini App
Создайте бота через @BotFather и назначьте URL как Mini App/Menu Button. SDK Telegram подключён. Сейчас данные пользователя берутся из initDataUnsafe только для отображения. НЕЛЬЗЯ выдавать права поставщика или подтверждать оплату по initDataUnsafe: сервер должен проверять подписанный Telegram initData. Не помещайте токен бота в JS или публичный репозиторий.

## Куда класть картинки
- Логотип: `assets/branding/logo.png` — прозрачный PNG, ориентир 400×140.
- Аватар по умолчанию: `assets/branding/default-avatar.png` — квадрат 256×256.
- Иконка категории: `catalog/<Категория>/preview.png` — квадрат.
- Иконка приложения: `catalog/<Категория>/<Приложение>/preview.png` — квадрат 512×512.
- Шапка приложения: `catalog/<Категория>/<Приложение>/header.png` — широкая, ориентир 1200×500.
- Скриншоты: `screen-01.png`, `screen-02.png` и т.д. в папке приложения.
- Короткое описание: `mdesc.txt`; полное: `desc.txt`.
- APK: `catalog/<Категория>/<Приложение>/<Поставщик>/<файл>.apk`.
- Данные автора: `accounts/<Поставщик>.json`. Имя папки поставщика и имя JSON должны совпадать.

## Формат accounts/John Doe.json
`{"display_name":"John Doe","telegram_username":"john_doe","telegram_user_id":"","avatar":"accounts/John Doe/avatar.png","version":"1.0"}`. Не храните там секреты и приватные данные.

## Добавление приложений
Добавьте объект в `data/catalog.json`, укажите `category`, `name`, `short`, `description`, `icon`, `header`, `screenshots` и массив `vendors`. Если поставщик один, диалог выбора пропускается; если несколько — показывается выбор. Путь к APK задаётся относительно корня сайта.

## Ограничения и решения
- GitHub Pages — статический хостинг: он не принимает публикации, не запускает серверный код и не хранит секреты.
- Скачивание APK не равно установке: Android попросит пользователя открыть APK и подтвердить установку.
- Публикация ведёт к @AlaganMarket_Bot, ручная модерация поставщика — к @AlaganMarket. Проверьте, что username правильные.
- Patreon подключён; DonationAlerts и криптоадрес пока заглушки.
- Wallet/TON: автоматическое подтверждение платежа требует TON Connect и серверной проверки транзакции (получатель, сумма, сеть, уникальный ID, защита от повторного зачёта). В этой версии оставлена ручная модерация.
- Для APK рекомендуется хранить версию, дату, размер, SHA-256, минимальную Android-версию, разрешения и лицензию. Публикуйте только файлы, на распространение которых есть права.

## Python-генератор каталога
Запустите `python tools/build_catalog.py` — он пересоберёт data/catalog.json по папкам каталога, описаниям и APK.


## Обновление интерфейса 0.2

- Нижняя панель: профиль, каталог и горизонтальная лента категорий.
- Категории остаются доступными при выборе одной из них; повторное нажатие снимает фильтр.
- Иконки приложений и категории используют `object-fit: contain` на белом фоне.
- Скриншоты отображаются в отдельных белых рамках без изменения пропорций.
- Логотип `assets/branding/logo.png` заполняет весь виджет хедера.

### Имена скриншотов

Поддерживаются `screen-01.png`, `screenshot_02.jpg`, `shot 03.webp`, а также `1.png`, `02.png` и подобные цифровые имена. Файлы `preview.*`, `header.*`, `icon.*` и `logo.*` не попадают в карусель.
